## 개요

LunarLander-v3 환경에서 PPO(Proximal Policy Optimization)를 직접 구현해 평균 보상 200점 이상을 달성하는 개인 학습 프로젝트다. Stable-Baselines3로 기준선을 확인하고, CleanRL 단일 파일 PPO를 분석한 뒤, 참고 없이 재구현해 원본과 학습 곡선을 비교한다.

목적은 RL 라이브러리 사용법이 아니라 PPO의 내부 동작(롤아웃 수집, GAE, 클리핑 손실, 엔트로피 보너스)을 코드 수준에서 이해하는 것이다. Mac Studio(Apple Silicon)에서 CPU 위주로 실행하며, GPU(MPS)는 선택 사항으로 둔다.

## 목표와 성공 기준

최종 목표는 직접 구현한 PPO가 LunarLander-v3에서 최근 100 에피소드 평균 보상 200점 이상을 달성하는 것이다.

| 목표 | 성공 기준 | 측정 방법 |
|---|---|---|
| SB3 기준선 확보 | 평균 보상 200점 이상 | SB3 PPO 1M 스텝 학습 후 100 에피소드 평가 |
| CleanRL PPO 이해 | 핵심 함수마다 주석 작성 완료 | 주석 달린 ppo_annotated.py 커밋 |
| PPO 재구현 | 참고 없이 작성한 코드가 200점 이상 달성 | 3개 시드 평균 학습 곡선 |
| 원본과 비교 | 동일 하이퍼파라미터에서 수렴 스텝 수 차이 20% 이내 | TensorBoard 곡선 비교 |
| 구성 요소 제거 실험 | GAE, 보상 정규화, 클리핑 각각 제거 시 영향 기록 | 실험 노트 작성 |

학습 외 기준: 전체 코드가 한 파일 500줄 이내이고, `python ppo.py` 한 줄로 재현된다.

## 범위

이 프로젝트는 이산 행동 공간의 PPO 한 가지에 집중하고, 다른 알고리즘과 연속 제어는 다루지 않는다.

**포함**
- LunarLander-v3 (이산 행동, 4개 액션) 환경
- Stable-Baselines3 PPO 기준선 실행
- CleanRL ppo.py 분석 및 주석
- PyTorch 기반 PPO 단일 파일 재구현 (벡터화 환경 포함)
- TensorBoard 로깅, 시드별 재현 실험
- 구성 요소 제거(ablation) 실험 3종

**제외**
- 연속 행동 공간 (LunarLanderContinuous, MuJoCo)
- DQN, SAC, TD3 등 다른 알고리즘
- 하이퍼파라미터 자동 탐색 (Optuna 등)
- 분산 학습, 멀티 프로세스 환경
- 트레이딩 등 커스텀 환경 (후속 프로젝트)

## 기술 스택과 환경 요구사항

Mac Studio(Apple Silicon, macOS 14 이상)에서 CPU만으로 전 과정이 돌아가도록 구성하고, MPS 가속은 선택 옵션으로 둔다. LunarLander 규모에서는 환경 스텝이 병목이라 CPU 학습이 오히려 빠른 경우가 많다.

| 구성 요소 | 선택 | 버전 | 비고 |
|---|---|---|---|
| 언어 | Python | 3.11 | uv 또는 venv로 격리 |
| 딥러닝 | PyTorch | 2.x | device = cpu 기본, mps 옵션 |
| 환경 | Gymnasium | 1.x | gymnasium[box2d] |
| Box2D 빌드 | swig | - | brew install swig 선행 필수 |
| 기준선 | Stable-Baselines3 | 2.x | 1단계에서만 사용 |
| 참고 구현 | CleanRL | main | ppo.py 단일 파일 |
| 로깅 | TensorBoard | - | SB3·CleanRL과 포맷 통일 |
| 실험 관리 | 시드 고정 + 설정 JSON | - | wandb는 선택 |

설치 명령:

```sh
brew install swig
uv venv && source .venv/bin/activate
uv pip install "gymnasium[box2d]" stable-baselines3 torch tensorboard
```

검증 기준: `gymnasium.make("LunarLander-v3")`가 에러 없이 생성되고, SB3 PPO가 1분 내 첫 로그를 출력한다.

## 기능 요구사항

재구현 PPO는 아래 8개 요구사항을 모두 만족해야 하며, 각 항목은 테스트 또는 로그로 확인한다.

| ID | 요구사항 | 확인 방법 |
|---|---|---|
| FR-1 | SyncVectorEnv로 N개(기본 4) 환경을 병렬 롤아웃한다 | 관측 shape이 (N, 8) |
| FR-2 | Actor-Critic 네트워크를 공유 없이 분리 구현한다 (64-64 MLP, Tanh) | 파라미터 수 로그 |
| FR-3 | 고정 길이 롤아웃(기본 128 스텝) 버퍼에 obs, action, logprob, reward, done, value를 저장한다 | 버퍼 shape 단위 테스트 |
| FR-4 | GAE(λ=0.95, γ=0.99)로 어드밴티지와 리턴을 계산한다 | 단순 케이스 수치 검증 테스트 |
| FR-5 | 클리핑 정책 손실(ε=0.2), 가치 손실, 엔트로피 보너스(0.01)를 합산한다 | 손실 3종 TensorBoard 기록 |
| FR-6 | 미니배치 K 에폭(기본 4) 업데이트와 어드밴티지 정규화를 수행한다 | approx_kl, clipfrac 기록 |
| FR-7 | 학습률 선형 감소와 글로벌 그래디언트 클리핑(0.5)을 적용한다 | 학습률 곡선 기록 |
| FR-8 | --seed, --total-timesteps, --device CLI 인자를 받고 시드를 전부 고정한다 | 같은 시드 2회 실행 시 동일 곡선 |

추가로 학습된 정책을 .pt로 저장하고, --eval 모드에서 100 에피소드 평균 보상을 출력한다.

각 단계는 통과 기준을 만족해야 다음으로 넘어가며, 3단계가 전체 시간의 절반을 차지한다. 주차는 저녁·주말 기준의 추정이라 실제 진도에 맞춰 조정한다.

## 평가와 실험 로깅

모든 실험은 시드 3개(0, 1, 2)로 돌리고, 평가는 결정적 정책(argmax)으로 100 에피소드 평균 보상을 기록한다.

| 지표 | 기록 주기 | 의미 |
|---|---|---|
| charts/episodic_return | 에피소드 종료마다 | 학습 진행도의 1차 지표 |
| losses/policy_loss, value_loss, entropy | 업데이트마다 | 손실 분해 |
| charts/approx_kl, clipfrac | 업데이트마다 | 정책 변화 폭, 0.02 초과 시 LR 점검 |
| charts/explained_variance | 업데이트마다 | 가치 함수 품질, 0.8 이상 목표 |
| charts/SPS | 1초마다 | 환경 스텝/초, 성능 회귀 감지 |

지표 이름은 CleanRL과 동일하게 맞춰 TensorBoard에서 원본 곡선과 겹쳐 볼 수 있게 한다. 제거 실험은 configs/에 설정 파일을 따로 두고 notes/04_ablation.md에 수렴 스텝과 최종 보상을 표로 남긴다.

## 리스크와 대응

가장 흔한 실패는 환경 설치 문제와 "돌아가는데 안 배우는" 조용한 버그다.

| 리스크 | 징후 | 대응 |
|---|---|---|
| Box2D 설치 실패 | pip install 중 swig 에러 | swig 먼저 설치, Python 3.11 사용, 실패 시 CartPole-v1로 먼저 진행 |
| 재구현이 수렴하지 않음 | 50만 스텝 후에도 보상 0 이하 | GAE 단위 테스트부터 확인, 어드밴티지 정규화·logprob 부호 점검, CleanRL과 변수별 값 비교 |
| MPS에서 속도 저하 | CPU보다 SPS가 낮음 | 기본 CPU 유지, MPS는 실험으로만 |
| 시드 고정 불완전 | 같은 시드로 곡선이 다름 | torch·numpy·env·action_space 시드 모두 고정 확인 |
| 범위 확장 유혹 | 연속 제어나 다른 알고리즘으로 새는 시간 | 범위 섹션 재확인, 확장은 완료 후로 미룸 |

## 확장 방향

이 프로젝트가 끝나면 같은 PPO 코드를 그대로 들고 다음 단계로 넘어간다.

1. 커스텀 트레이딩 환경: Gymnasium 인터페이스로 주가 데이터 환경을 만들고 직접 짠 PPO를 연결한다.
2. 연속 행동 PPO: LunarLanderContinuous-v3로 가우시안 정책 헤드만 교체해 확장한다.
3. MLX 포팅: PyTorch 버전과 동일 결과가 나오는지 비교하며 프레임워크 내부를 익힌다.
